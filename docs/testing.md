# الاختبار

## ما يعمل اليوم (مشغَّل ومُتحقق منه في بيئة التطوير الحالية)

```bash
cd apps/api && npm install        # يتطلب شبكة
npm run test:domain               # tsx --test src/domain/*.test.ts  → 35 اختبارًا
npm run typecheck                 # tsc --noEmit (strict)
```

نتيجة آخر تشغيل في بيئة الكتابة: **35 نجاح / 0 فشل**، و`tsc` بوضع strict بلا أخطاء. تغطي: النقود والتقريب، محرك التسعير بأنماطه الثلاثة، آلة حالات الرحلة وصلاحيات كل فاعل، رمز البدء (انتهاء، قفل، عدم تطابق)، دفتر السائق والتسويات.

> قرار: اختبارات النطاق النقي تستخدم `node:test` (بلا اعتماديات، تعمل دون شبكة). اختبارات وحدات Nest والتكامل تستخدم **Jest + Supertest** كما في المتطلبات.

## ما لم يُنفَّذ بعد (مخطط، لا يُدّعى نجاحه)

| الفئة | المحتوى | المتطلب |
|---|---|---|
| ترحيلات | تطبيق `0001`/`0002` على قاعدة جديدة، ثم إعادة التشغيل (idempotent runner) | PostgreSQL+PostGIS (`db_test` في Compose) |
| تكامل الخادم | تسجيل/دخول، RBAC، طلب رحلة، تسعير، قبول/رفض، بدء/إنهاء، إلغاء، دفع نقدي، قيود مالية | Nest + Jest + Supertest + `db_test` (لا SQLite) |
| **التزامن** | `Promise.all` من N اتصالات حقيقية: (1) سائقان يقبلان العرض نفسه؛ (2) سائق يقبل عرضين لرحلتين؛ (3) إعادة `POST /rides` بنفس المفتاح؛ (4) حدث/إشعار مكرر؛ (5) إعادة ترحيل قيود الرحلة؛ (6) القبول لحظة انتهاء العرض. المتوقع: نجاح واحد بالضبط والباقي `409`، ولا صفوف زائدة | `db_test` |
| محفزات القاعدة | محاولة `UPDATE/DELETE` على السجلات الثابتة، تعديل تعرفة منشورة، انتقال حالة غير شرعي، إسناد لسائق موقوف | `db_test` |
| الهاتف | RTL، انقطاع الإنترنت، رفض إذن الموقع، إعادة فتح التطبيق أثناء رحلة، لا سائقين، إلغاء، إشعارات متأخرة | Flutter SDK |
| الإدارة | حماية الصفحات، منع تصعيد الصلاحيات، تدقيق التعليق والتسويات | Next.js + Playwright |
| الأمان | قائمة ASVS/MASVS مختارة وتشغيلها يدويًا ثم آليًا | |

## CI (مخطط)

مهام: lint (ESLint/Prettier) ← typecheck ← `test:domain` ← ترحيلات على PostGIS ← Jest/Supertest ← Flutter analyze/test ← Playwright. لا دمج دون نجاح الكل.
